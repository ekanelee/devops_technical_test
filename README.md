# PHP-FPM + Nginx on Google Cloud Run (Terraform + GitHub Actions)
 
A small PHP application served by Nginx and PHP-FPM on **Cloud Run**, backed by **Cloud SQL (MySQL)**, with static files in **Cloud Storage**, fronted by a **global HTTP(S) load balancer**. Everything is created with **Terraform** and deployed by a **GitHub Actions** pipeline that authenticates to Google Cloud without any JSON key.
 
> Status: Terraform (flat resources, then modules) and the CI/CD pipeline are implemented. The Bash script, `dr.md` and `extra.md` are added in later phases (see [Roadmap](#roadmap)).
 
## Architecture
 
```
Internet
   |
Global external HTTP(S) Load Balancer (static IP)
   |  URL map
   |-- /static/*  --> Backend bucket (+ Cloud CDN) --> Cloud Storage bucket
   |-- /*         --> Serverless NEG --> Cloud Run service (app-<env>)
                                         |-- nginx   (ingress container, :8080)
                                         |-- php-fpm (sidecar, :9000, same network namespace)
                                                |  unix socket /cloudsql/<connection-name>
                                                v
                                          Cloud SQL for MySQL 8
```
 
Key design choices:
 
| Choice | Reason |
|---|---|
| Nginx ingress + PHP-FPM sidecar in one Cloud Run service | PHP-FPM speaks FastCGI, not HTTP, so Nginx is required; sidecars share localhost, so no network hop |
| Cloud SQL connector (unix socket) | No IP allow-lists; access controlled by IAM (`roles/cloudsql.client`) |
| DB password generated by Terraform, stored in Secret Manager | The production password never appears in the repo or in GitHub |
| Artifact Registry | Google Container Registry has been shut down and replaced by it |
| Workload Identity Federation (WIF) | Keyless CI authentication, restricted to this repository |
| Deployment through Terraform (`image_tag` variable) | Single source of truth, no drift between code and what runs |
| One Terraform root + `environments/<env>.tfvars` + `<env>.backend.hcl` | Same code for every environment, separate state file per environment |
| Cloud Run ingress limited to the load balancer | The `run.app` URL is not reachable from the internet, so CDN and future WAF rules cannot be bypassed |
 
Cloud Run has no fixed public IP of its own: the application's public IP is the **load balancer's global static IP** (`terraform output lb_ip_address`).

## Prerequisites
 
- A GCP project with **billing enabled** (the project is used as is; creating one is out of scope)
- `gcloud`, `terraform` >= 1.6, `docker`, `git`, and optionally the GitHub CLI (`gh`)
- A GitHub repository (fork or copy of this one)
## Replicate the project step by step
 
### 1. Authenticate and enable the two APIs Terraform needs to enable the rest
 
```bash
gcloud auth login
gcloud auth application-default login
gcloud config set project <PROJECT_ID>
gcloud services enable serviceusage.googleapis.com cloudresourcemanager.googleapis.com
```
 
### 2. Bootstrap (run once, local state)
 
This creates the remote-state bucket, Artifact Registry, enabled APIs, and the keyless GitHub identity.
 
```bash
cd terraform/bootstrap
cp terraform.tfvars.example terraform.tfvars   # set project_id and github_repo (owner/name, case-sensitive)
terraform init
terraform apply
terraform output
```
 
### 3. Configure GitHub
 
Secrets: `WIF_PROVIDER` (output `wif_provider`), `CI_SA_EMAIL` (output `ci_service_account_email`), `CI_DB_PASSWORD` (any random value; used only by the throwaway test database).
Variables: `GCP_PROJECT_ID`, `GCP_REGION` (for example `europe-west1`).
 
```bash
gh secret set WIF_PROVIDER --body "$(terraform output -raw wif_provider)"
gh secret set CI_SA_EMAIL  --body "$(terraform output -raw ci_service_account_email)"
gh secret set CI_DB_PASSWORD --body "$(openssl rand -hex 16)"
gh variable set GCP_PROJECT_ID --body "<PROJECT_ID>"
gh variable set GCP_REGION     --body "europe-west1"
```
 
Create two GitHub Environments (*Settings > Environments*): `dev` (no rules) and `prod` (required reviewers).
 
### 4. Point Terraform at the remote state
 
Edit `terraform/environments/dev.backend.hcl` and set `bucket` to the `tfstate_bucket` output (`<PROJECT_ID>-tfstate`).
 
### 5. Test the application locally (no cloud needed)
 
```bash
docker compose up --build -d
curl localhost:8080/            # JSON with the PHP version
curl localhost:8080/healthz     # ok (answered by Nginx)
curl localhost:8080/readyz      # database check; may need a few seconds while MySQL starts
docker compose down
```
 
### 6. First deployment
 
Push to `main`; the pipeline builds and pushes both images, then applies Terraform. To deploy by hand instead:
 
```bash
REGISTRY=europe-west1-docker.pkg.dev/<PROJECT_ID>/app
TAG=$(git rev-parse --short HEAD)
gcloud auth configure-docker europe-west1-docker.pkg.dev
docker build -f docker/php-fpm/Dockerfile -t $REGISTRY/php-fpm:$TAG .   # add --platform linux/amd64 on ARM machines
docker build -f docker/nginx/Dockerfile   -t $REGISTRY/nginx:$TAG .
docker push $REGISTRY/php-fpm:$TAG && docker push $REGISTRY/nginx:$TAG
 
cd terraform
export TF_VAR_project_id=<PROJECT_ID> TF_VAR_environment=dev TF_VAR_image_tag=$TAG
terraform init -reconfigure -backend-config=environments/dev.backend.hcl
terraform apply -var-file=environments/dev.tfvars
```
 
Do not run a local apply while the pipeline runs: they share one state lock.
 
### 7. Access the application
 
```bash
cd terraform && terraform output app_url
curl "$(terraform output -raw app_url)/"          # app info
curl "$(terraform output -raw app_url)/readyz"    # {"status":"ready","database":"ok"}
curl "$(terraform output -raw app_url)/static/hello.txt"   # served from the bucket via the load balancer
```
 
A new load balancer can take a few minutes before it answers (404 or 502 at first is normal).
 
### 7b. Retrieve the public IP with the Bash script

Cloud Run has no fixed public IP of its own: the application's public IP is the global address of the load balancer. The script reads it from the address Terraform reserved (`app-<env>-ip`).

    gcloud auth login                       # once, if you are not logged in
    ./scripts/get-ip.sh dev                 # prints the IP, for example 34.x.x.x
    curl "http://$(./scripts/get-ip.sh dev)/readyz"

- Argument: `dev` or `prod` (anything else prints the usage message and exits with code 1).
- Project: taken from `GCP_PROJECT_ID`, otherwise from `gcloud config`.
- Output: only the IP goes to standard output, so it can be used inside `$(...)`; messages go to the screen and to `get-ip.log` with timestamps.
- Errors handled: missing or invalid argument, `gcloud` not installed, no project set, address not found (environment not deployed, wrong project or not logged in).

### 8. Clean up (the Cloud SQL instance and the load balancer cost money while idle)
 
```bash
cd terraform
terraform destroy -var-file=environments/dev.tfvars
```
The state bucket has `prevent_destroy`; remove it deliberately from `bootstrap/` if you want a full teardown.
 
## CI/CD pipeline (`.github/workflows/ci-cd.yml`)
 
| Trigger | What runs |
|---|---|
| Pull request | PHP tests and Terraform format/validate only (no deployment) |
| Push to `main` (docs-only changes ignored) | Tests, then build and push images (tagged with the commit SHA), then deploy to `dev` with Terraform, then sync static files and run a smoke test |
| Manual run (`workflow_dispatch`) | Choose `dev` or `prod`; `prod` waits for approval |
 
Environment differences are injected at run time: `-backend-config=environments/<env>.backend.hcl` selects the state file and `-var-file=environments/<env>.tfvars` selects sizing and settings. The image tag and project ID are passed as `TF_VAR_*` variables.
 
Secrets inventory:
 
| Item | Location | Purpose |
|---|---|---|
| `WIF_PROVIDER`, `CI_SA_EMAIL` | GitHub secrets | Keyless authentication to Google Cloud |
| `CI_DB_PASSWORD` | GitHub secret | Throwaway MySQL used by the integration test |
| `GCP_PROJECT_ID`, `GCP_REGION` | GitHub variables | Non-sensitive configuration |
| Production DB password | Secret Manager (generated by Terraform) | Read by Cloud Run at runtime, never passes through GitHub |
 
## Difficulties faced and how they were solved
 
### 1. No billing account at the start
 
`terraform apply` of the bootstrap layer failed because the project had no billing account and the payment card could not be validated immediately. All code was written and validated offline in the meantime with `terraform init -backend=false`, `terraform fmt` and `terraform validate`, and the application was tested locally with `docker compose`. Once billing was available, the resources were applied in order: bootstrap, then the application stack.
 
### 2. Cloud Run revision failed its startup probe (php-fpm, port 9000)
 
**Symptom.** The first deployment from the pipeline failed with:
 
```
STARTUP TCP probe failed 3 times consecutively for container "php-fpm" on port 9000.
The instance was not started. Connection failed with status DEADLINE_EXCEEDED.
Error code 9 ... Revision 'app-dev-00001' is not ready and cannot serve traffic.
```
 
**Cause.** The PHP-FPM pool was configured with `listen = 127.0.0.1:9000` (loopback only). Cloud Run's startup probe reaches the container through the instance's network interface, not through loopback, so the probe could not connect even though PHP-FPM itself was running.
 
**Fix.** PHP-FPM now listens on all interfaces of the instance (`listen = 9000` in `docker/php-fpm/zzz-app.conf`). This is safe in this layout because only the ingress container's port (8080) is routed to the outside; port 9000 is reachable only from containers in the same instance. Nginx still uses `fastcgi_pass 127.0.0.1:9000`, which works because all interfaces include loopback. The failed service was left tainted in the Terraform state, so the next pipeline run replaced it.
 
**Lesson.** A port that must pass a platform health probe has to listen on `0.0.0.0`, even for sidecars.
 
## Troubleshooting
 
| Symptom | Likely cause | Fix |
|---|---|---|
| Revision fails its startup probe | Container not listening on all interfaces, wrong port, or crash at start | Read the revision logs (filter by `container_name`); see difficulty 2 |
| 502 from the load balancer | Nginx not on 8080, or PHP-FPM unreachable | Check container logs and `fastcgi_pass` |
| `File not found.` | `SCRIPT_FILENAME` differs from the path in the PHP container | Align it with the PHP image's `WORKDIR` |
| PHP environment variables are empty | `clear_env` is not `no` | Set `clear_env = no` in the pool file |
| DB socket `No such file` | `/cloudsql` volume not mounted in the PHP container | Mount it in the container that connects |
| `unauthorized_client` in the auth step | `WIF_PROVIDER` uses the project ID instead of the number, repo name mismatch (case), or propagation delay | Use the `wif_provider` output as is, check `github_repo`, wait 5 minutes |
| `Permission 'x' denied` in Terraform | CI service account lacks a role | Add the role to `ci_roles` in `terraform/bootstrap/ci.tf` and re-apply the bootstrap |
| `Error acquiring the state lock` | Another apply is running, or a run crashed | Wait, or `terraform force-unlock <ID>` when sure |
| 403 on the application | `allUsers` invoker blocked by an organisation policy | Document as a limitation or use an identity-aware proxy |
| Managed certificate stuck in `PROVISIONING` | DNS does not point to the load balancer IP | Fix DNS and wait up to about an hour |
| get-ip.sh says it could not read the address | Environment not deployed, wrong project, or not logged in | Run gcloud auth login, check GCP_PROJECT_ID, and make sure terraform apply completed for that environment |
| bad interpreter or \r: command not found | Windows line endings in the script | Run sed -i 's/\r$//' scripts/get-ip.sh and keep the .gitattributes rule |

## Known limitations and production improvements
 
- CI service account has broad roles (including project IAM admin) so Terraform can manage everything; split plan and apply identities for production.
- Cloud SQL uses a public IP with no authorized networks (connector-only access); move to private IP with Direct VPC egress.
- No monitoring or alerting yet: add uptime checks on `/readyz`, alert policies for 5xx and latency, and a dashboard.
- No WAF: add Cloud Armor on the backend service.
- HTTPS needs a domain: set `enable_https = true` and `domain` once DNS points at the load balancer IP, and add an HTTP-to-HTTPS redirect.
- The DB password is generated by Terraform and therefore exists in the state file: keep the state bucket private (it is), or use IAM database authentication.
